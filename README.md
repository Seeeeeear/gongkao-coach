# 考公做题分析器

**不是题库 App。** 你已经有粉笔、华图和纸质真题卷了，缺的不是题，而是**做完题之后没人给你做分析**。

这个工具解决的就是这件事：

> 拍下/粘贴你做错的题 → AI 告诉你**这道题在考什么、最快的解法是什么、你属于哪一类错误** → 错误自动归类 → 攒够数据后生成**阶段弱点报告**，告诉你先治哪个毛病。

---

## 核心功能

| 功能 | 说明 |
|---|---|
| 📷 **拍题分析** | 拍照或粘贴题目，AI 还原题干、判断考点、给出**快解方法**（带步骤和秒数） |
| 🧠 **错因归因** | 12 类错因体系（看错问法 / 单位量级 / 找错数据 / 公式用错 / 计算失误 / 方法超时 / 推理漏洞 / 选项陷阱 / 粗心 / 时间恐慌…），每类都给出**下次怎么防** |
| ✏️ **错因可修正** | AI 判错了可以自己点着改，改完统计立刻跟着变（AI 归因一定会错，这个口子必须留） |
| 🔁 **重做与掌握** | 隔几天遮住答案重做一遍；做对了标记「已掌握」，**不再计入弱点统计**——治好的毛病不该永远挂在报告上 |
| 📊 **弱点报告** | 错因频率分布、模块分布、高频考点、近 7 天趋势，以及 AI 阶段诊断（先治什么、时间怎么分配、这周怎么练） |
| 📚 **技巧库** | 内置截位直除、特征数字法、比重变化、平均数增长率等速算方法，可自己增删 |
| ✍️ **申论批改** | 粘答案或拍手写稿，按阅卷人标准给分、指漏点、**逐句点评并给出改写后的句子** |
| 💬 **问老师** | 每道题都能继续追问，AI 带着题目上下文回答 |
| 🎓 **方法流派** | 可选定老师的方法体系（资料分析速算法 / 白鹭申论 / 国考评分标准），AI 用那一套术语和流程讲，避免方法混着学 |
| 🧪 **示例模式** | 不配 Key 也能先看一份完整分析 + 18 条示例错题的统计效果 |
| 📶 **离线启动** | 打开过一次后，应用外壳缓存在本机，断网也能启动 |

## 方法流派（技能包）

不同老师的方法体系不一样（截位怎么截、要不要写总括句）。**选定一个流派后，AI 会用那一套流程和术语讲** —— 这对全职备考很重要，因为方法混着学是最大的浪费。

| 流派 | 来源 | 许可 |
|---|---|---|
| 通用速算法（资料分析） | 公开速算方法体系，自行整理 | 自建 |
| 白鹭申论 | 提炼自 [Shenlun.skill](https://github.com/coffe-d/Shenlun.skill) | MIT |
| 国考申论评分标准 | 公开资料整理 | 自建 |
| 花生十三 · 资料分析 | **未收录**（原因见下） | 该仓库无 LICENSE |

### 关于花生十三那个包（重要）

GitHub 上确实有 [`huasheng13-skill`](https://github.com/WangJunqing-coder/huasheng13-skill)（898 star），但：

1. **该仓库没有 LICENSE** —— GitHub 的规则是「没有许可证 = 默认保留所有权利」，不等于可以随便用
2. 它自述「基于花生十三公开教学体系、**课程资料**、历年真题整理」，本身已踩在老师的商业内容上
3. 你的仓库是 public，收录它等于公开传播

所以索引里只留了一条**禁用占位**并说明原因。**如果这是你已有的课程内容，你可以在本地自己加一个包**，格式照 `skills/packs/general-data.json` 抄。

### 设计要点

- **索引内联、内容按需**：索引约 2KB 随应用加载；流派内容 8-12KB 按需 fetch，抓到后缓存进 IndexedDB，**离线可用**。这样手机首屏不会因为技能包变大而变慢
- 申论包**保留原作者的证据分级**：标 `unverified` 的方法（如「综合分析＝3W 十六字方针」）不得用作扣分理由
- 国考评分标准包里有**诚实标注**：国家公务员局从未公开申论评分细则，四类文分档是培训行业归纳的惯例，不是官方文件 —— 批改时会如实说明

新增流派：写 `skills/packs/<id>.json`，在 `SKILLS_INDEX.packs` 加一条索引，跑 `npm run verify`。

## 快速开始（3 步）

```bash
# 1. 装依赖（这个沙箱/受限环境里需要 --ignore-scripts）
npm install --ignore-scripts

# 2. 生成运行库和样式（已经生成过，改了配置才需要重跑）
npm run vendor    # 复制 React 到 vendor/
npm run css       # 生成 styles.css

# 3. 启动
npm run dev       # 编译 app.jsx 并启动本地服务器
```

打开 <http://localhost:5173>，同一 WiFi 下手机访问终端里提示的 `http://192.168.x.x:5173`。

**第一次使用**：进入「设置」→ 填 DeepSeek 的 API Key（[platform.deepseek.com](https://platform.deepseek.com) 注册后创建）→ 点「测试连接」。

## 为什么是"免构建"

原本用 Vite，但当前开发沙箱禁止 esbuild 启动子进程（`spawn EPERM`），构建和 dev server 都起不来。
于是改成：

- 源码是单个 `app.jsx`（用 JSX 写，可读性不受影响）；
- `npm run build` 用 Babel 把它编译成 `app.js`（87KB）；
- 浏览器直接加载 `app.js`，**不需要 Babel，也不需要打包器**；
- 部署时把源码推到静态托管即可，线上不跑任何构建。

副作用是**手机首次加载从 5MB 降到约 250KB**，比原方案还快。

改代码的流程：

```bash
npm run watch     # 监听 app.jsx，改完自动重新编译 app.js
```

> ⚠️ 改代码请改 `app.jsx`，**不要直接改 `app.js`**（它是自动生成的，会被覆盖）。

## 技术选型

| 项 | 选择 | 原因 |
|---|---|---|
| 前端 | React 18 + Tailwind 3（UMD/预编译 CSS） | 无需构建工具链 |
| 数据 | **localStorage，全部存在本机** | 你要求"只存手机上、不上云" |
| AI | 你自己的 DeepSeek API Key | 按量付费，正常用每月几块钱 |
| 后端 | **没有后端** | 静态托管即可，不用备案、不用域名 |
| 部署 | Cloudflare Pages / GitHub Pages | 免费，自带 `*.pages.dev` 网址 |

### 关于 API Key 安全

Key 存在你自己浏览器的 localStorage 里，不会上传到任何服务器。
但如果把网站**公开**给别人用，**不要**把自己的 Key 写进去（静态网页的代码人人可见）。
给别人用的正确做法是配一个 Cloudflare Worker 代理（「设置」页留了「代理地址」输入框），Key 放 Worker 的环境变量里。

## 部署到手机可用

**不想看长文就直接打开 [`部署指南.md`](./部署指南.md)** —— 那是给非技术用户写的一步步图文说明（推 GitHub → Cloudflare Pages → 手机加桌面）。

项目所有资源都用**相对路径**，所以放在仓库根目录或子路径（`/仓库名/`）都能正常打开。

### 方式一 · Cloudflare Pages（推荐，国内访问更稳）

1. 把项目推到 GitHub（`node_modules/` 已在 `.gitignore` 里，不要提交）；
2. Cloudflare Dashboard → Workers & Pages → Create → Pages → 连接该仓库；
3. **构建命令留空**，输出目录填 `/`（产物已提交，线上不需要构建）；
4. 得到 `https://你的项目.pages.dev`。

`_headers` 文件会自动让 `sw.js` 不被缓存 —— 这样你更新代码后手机不会还跑旧版。

### 方式二 · GitHub Pages

1. 仓库 Settings → Pages → Source 选 **Deploy from a branch**；
2. 分支选 `main`，目录选 `/ (root)`，保存；
3. 访问 `https://你的用户名.github.io/仓库名/`。

`.nojekyll` 已经放好了（告诉 GitHub Pages 不要用 Jekyll 处理，避免静态资源被忽略）。

### 装到手机上

手机浏览器打开网址 → 菜单 → **「添加到桌面」**，图标就像 App 一样。

> 鸿蒙自带浏览器上，桌面图标可能仍带地址栏、Service Worker 支持也不完整（华为官方论坛有反馈），
> 这是 HarmonyOS 的系统限制，**功能不受影响**，只是离线能力弱一些。

## 离线能力

`sw.js` 会把应用外壳（HTML/CSS/JS/React）缓存起来：

- 安卓平板上：**打开过一次后，断网也能启动**，可以查看已有错题和技巧库；
- 鸿蒙手机上：受系统限制，离线可能不生效；
- AI 分析、申论批改**必须联网**（要调用模型），这个没有办法离线。

更新代码后如果手机上还是旧界面，把 `sw.js` 里的 `VERSION` 改成 `v2` 再部署即可。

## 没配 API Key 也能先看效果

- 「分析」页底部有 **「先看一份示例分析」** 按钮，直接展示一份完整的分析结果（快解步骤、出题人的坑、错题本一句话）；
- 「设置」页有 **「载入示例数据」**，会铺 18 条示例错题，让你立刻看到错因分布、模块统计和 7 天趋势；
- 「弱点」页空状态也有入口。

看完可以一键「清空所有记录」。

## 开发与自检

```bash
npm run watch     # 改 app.jsx 自动重新编译
npm run verify    # 编译 + 语法校验 + 用 jsdom 真实渲染一遍（推荐每次改完都跑）
```

`npm run verify` 会在假浏览器里真实执行 `app.js`，然后逐个点开 5 个 tab、
点开示例分析、载入示例数据，确认**没有白屏、没有 JS 报错、关键文案都渲染出来了**。
比单纯的语法检查靠谱得多 —— 它真的抓到过一个 bug：弱点页空状态漏了页面标题。
